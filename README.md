# 工作咩闹钟的Windows实时音频推送上位机
用于工作咩闹钟Linux端接收Windows电脑的实时播放的音频

给电脑当音箱用,类似mac上的AirPlay  
延迟比蓝牙低,音质比蓝牙好  
极低占用,0.3%的CPU和1.7M内存,应用不到400K  

按回车键可以重连,键盘的上下键可以调音量  
运行时会劫持媒体键盘上的音量加减键,用于调节音箱的音量,不调系统音量,按静音按钮可以重连  

如果你发现在游戏中键盘劫持失效，请用管理员权限启动loopbackPost

## 使用方法
在右侧Release中下载，双击打开，输入工作咩闹钟的Web后台地址按回车即可  
注意需要带`/aplay`后缀(4.0开始会自动补上)，比如  
```
http://192.168.1.147:8080/aplay
```
而Android端，端口和Web后台不同，是`8880`，比如  
```
http://192.168.1.147:8880/aplay
```
另外还可以作为程序的第一个参数传入，方便在 任务计划程序 中设置成开机启动，比如
```
loopbackPost.exe http://192.168.1.147:8080/aplay
```
#### 一对多和单声道
第一个参数可以用半角逗号分隔多个地址，每个地址使用一个独立线程发送。地址前加 `L` 或 `R`（大写）表示只发送左声道或右声道单声道，适合左右两只音箱分别接收：
```
loopbackPost.exe Lhttp://192.168.1.147:8080/aplay,Rhttp://192.168.1.148:8080/aplay
```
不加前缀的地址仍然发送原始多声道（通常是立体声）：
```
loopbackPost.exe http://192.168.1.147:8080/aplay,http://192.168.1.148:8080/aplay
```
#### 如果你需要增加延迟
比如跟现有的蓝牙音箱同步什么的,可以增加第二个参数的发送阈值,如果你的设备性能特别好,还可以把他降的比默认的5ms还低
```
loopbackPost.exe http://192.168.1.147:8080/aplay 100
```
#### 音频会自动加速来同步，减少延迟，如果你的Wi-Fi稀巴烂，你可以将默认20的同步阈值改大比如改成200，避免音频加速  
程序启动后会自动将自身进程优先级设为“高”,如果是CPU比较弱,也可以在任务管理器详细信息中找到,右键把优先级调成实时  
```
loopbackPost.exe http://192.168.1.152:8880/aplay 5 200
```
